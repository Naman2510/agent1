# Co-Scheduler Scorecard (pre-registered)

This file was committed **before** the co-scheduler it scores was
written, so that the metrics and pass thresholds could not be tuned to
the results. Its git history is the record of that ordering. The
measured results and the computed score live in
`results/coschedule_scorecard.md`, generated by script from simulation
output, never hand-entered.

## What is being scored

A **concurrent CPU + accelerator co-scheduler**. Every scheduler built in
this project so far assumed the two engines take turns: each task goes to
one engine, then the next task starts. Measurement shows the accelerator
is busy for only part of each task it runs (16 of 216 cycles for vecadd
N=16; 512 of 1,458 for matmul N=8), and the CPU sits in a polling loop
for that whole time. The accelerator runs autonomously once started, and
its only constraint (`docs/accelerator.md`) is that the CPU must not
rewrite its operand window while it is busy. RAM is a separate path. So
the CPU can execute *other tasks* during those busy windows.

The co-scheduler is an offline planner plus a code generator. The planner
assigns each task to the accelerator, to the CPU in series, or to the
CPU **inside a specific accelerator task's busy window**, minimizing the
predicted total cycle count from per-task costs measured in simulation.
The generator emits the corresponding RISC-V program. No RTL changes.

## Streams and baselines

- Streams, all fixed before results: Phase 15's 6-workload stream,
  Phase 16's 12-workload stream, and the **full set of all 24 workloads**
  this project has measured (vecadd/dot N = 1, 2, 3, 4, 6, 8, 12, 16, 32,
  64; matmul N = 1, 2, 4, 8). The full set is used precisely because it
  is not hand-picked.
- Core configurations: the default RV32I core, and the core with the
  optional hardware `MUL` (`ENABLE_MUL=1`).
- Baselines, all *measured* on the same streams with the same per-task
  code and output layout: **always-accelerator** (serial) and the
  **serial oracle** (every task on whichever engine is faster for it,
  one at a time). The serial oracle is the best that any scheduler which
  doesn't overlap the two engines can possibly do.

## Metrics (10 points each, pass/fail, 100 total)

| # | Metric | Pass threshold |
|---|---|---|
| 1 | **Correctness** | Every output word of every task, in every co-scheduled and baseline program, matches its Python-computed value, on both Icarus Verilog and Verilator. |
| 2 | **Never worse** | On every stream x core configuration, the measured co-schedule is no slower than the measured serial oracle. |
| 3 | **Real speedup (RV32I)** | Full 24-workload stream, default core: measured co-schedule at least **5%** faster than the measured serial oracle. |
| 4 | **Real speedup (MUL core)** | Same stream, `ENABLE_MUL=1` core: at least **5%** faster than that core's measured serial oracle. |
| 5 | **Beats the old ceiling** | Full stream, default core: the co-schedule's gain over the serial oracle is at least **10x** the serial oracle's own gain over always-accelerator (the entire ceiling of every serial scheduler in this project). |
| 6 | **Model fidelity** | For every co-scheduled program, the planner's predicted cycle count is within **5%** of the measured count. |
| 7 | **Planner quality** | On the Phase 15 stream (small enough to enumerate every placement), the planner's choice is within **1%** of the exhaustive model optimum, for both core configurations. |
| 8 | **Zero hardware cost** | No file under `rtl/` is changed (so no area, timing or verification cost). |
| 9 | **Reproducible** | A single make target regenerates profiles, plans, programs, correctness checks and measurements. Two consecutive runs give identical numbers, and the full `make demo` regression passes. |
| 10 | **Honest reporting** | The generated report shows every stream x core result, including any that miss a threshold, plus the model-error table, and states the method's limits. |

A metric that fails is reported as failed. The response to a failure is
to improve the product, never to edit this file.
